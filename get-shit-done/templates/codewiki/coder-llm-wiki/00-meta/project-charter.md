# 项目章程

## 目标
建立一个基于源码证据、可 review、可长期维护的仓库 wiki，支撑后续开发和维护。

## 非目标
- 不产出没有证据的纯文字总结。
- 代码不支持时，不猜测设计意图。
- 不在每次运行时重写整套 wiki。

## 文档规则
- 事实必须由代码、配置、测试或其他仓库来源支撑。
- 不确定内容写入 `开放问题`，不要伪装成事实。
- 优先使用稳定模板，便于比较和再生成。
- 文件路径和重要 token 必须保持精确。

## 证据规则
- 尽量使用文件路径和行号范围。
- 优先使用一手来源：入口点、配置、测试和核心实现。
- 如果结论由多个文件共同推断得出，必须全部引用。

## 任务规则
- 以小任务推进，并保证可恢复。
- 每个任务完成后将结果落盘。
- 每个任务后更新进度和队列状态。
- 阻塞任务必须明确标记原因。

## 完成标准
- 模块文档只有在 evidence 已链接、问题已记录后才能标记为 `done`。
- 流程文档只有在主路径和失败路径都描述后才能标记为 `done`。
- review 只有在冲突和未解决缺口都记录后才能标记为 `done`。

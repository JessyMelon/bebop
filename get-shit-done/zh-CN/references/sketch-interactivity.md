# 让 Sketch 有生命感

静态 mockup 几乎比截图好不了多少。Sketch 中的每个交互元素都必须对交互作出响应。

## 必需的交互性

| 元素 | 必备项 |
|------|--------|
| 按钮 | 带可见反馈的点击处理逻辑（状态变化、动画、toast） |
| 表单 | blur 时做输入校验，提交处理逻辑显示成功状态 |
| 列表 | 添加/删除项目、空状态、填充状态 |
| 切换开关 | 可用的切换逻辑，并有可见的状态变化 |
| 标签页/导航 | 点击切换内容 |
| 模态框/抽屉 | 带过渡效果的打开/关闭 |
| 悬停状态 | 每个可点击元素都需要 hover 效果 |
| 下拉框 | 打开/关闭、选择项目 |

## 过渡效果

给交互元素默认加上 `transition: all 0.15s ease`。细微的动效会让 sketch 更像真实产品，也更容易判断交互模式是否有效。

## 模拟后端

如果 sketch 里有一个 “Save” 按钮，点击后应该先显示一个短暂的 loading 状态，再显示成功消息。如果有搜索栏，输入时应该过滤硬编码结果。目标是让人感受到完整交互闭环，而不只是看到静止状态。

## 状态切换

如果 sketch 有多个状态（empty、loading、populated、error），加入可以在这些状态间切换的按钮，并清晰标注每种状态。这样用户才能体验设计在不同数据条件下如何表现。

## 实现方式

在内联 `<script>` 标签中使用原生 JS。不用框架，不要构建步骤。保持简单：

```html
<script>
  // 切换面板
  document.querySelector('.panel-toggle').addEventListener('click', (e) => {
    e.target.closest('.panel').classList.toggle('collapsed');
  });
</script>
```

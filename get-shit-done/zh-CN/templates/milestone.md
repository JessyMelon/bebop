# 里程碑条目模板

完成里程碑时，将此条目添加到 `.planning/MILESTONES.md`：

```markdown
## v[X.Y] [名称] (Shipped: YYYY-MM-DD)

**已交付：** [用一句话描述已发布内容]

**已完成阶段：** [X-Y]（共 [Z] 个计划）

**关键成果：**
- [主要成果 1]
- [主要成果 2]
- [主要成果 3]
- [主要成果 4]

**统计：**
- [X] 个文件已创建/修改
- [Y] 行代码（主要语言）
- [Z] 个阶段，[N] 个计划，[M] 个任务
- 从开始到发布（或从里程碑到里程碑）共 [D] 天

**Git 范围：** `feat(XX-XX)` → `feat(YY-YY)`

**下一步：** [简述下一个里程碑目标，或填写 "项目完成"]

---
```

<structure>
如果 `MILESTONES.md` 不存在，则创建它并写入以下标题：

```markdown
# 项目里程碑：[项目名称]

[条目按时间倒序排列 - 最新的在最前]
```
</structure>

<guidelines>
**何时创建里程碑：**
- 初始 v1.0 MVP 已发布
- 主版本发布（v2.0、v3.0）
- 重要功能里程碑（v1.1、v1.2）
- 在归档规划之前（记录已发布内容）

**不要为以下情况创建里程碑：**
- 单个阶段完成（正常工作流）
- 进行中的工作（等到发布后）
- 不构成一次发布的小型 bug 修复

**应包含的统计信息：**
- 统计修改文件数：`git diff --stat feat(XX-XX)..feat(YY-YY) | tail -1`
- 统计 LOC：`find . -name "*.swift" -o -name "*.ts" | xargs wc -l`（或相应扩展名）
- 来自 ROADMAP 的阶段/计划/任务数量
- 从首个阶段提交到最后一个阶段提交的时间线

**Git 范围格式：**
- 从该里程碑的第一个提交 → 最后一个提交
- 示例：阶段 1-4 可写为 `feat(01-01)` → `feat(04-01)`
</guidelines>

<example>
```markdown
# 项目里程碑：WeatherBar

## v1.1 安全与打磨 (Shipped: 2025-12-10)

**已交付：** 通过 Keychain 集成和全面错误处理完成安全加固

**已完成阶段：** 5-6（共 3 个计划）

**关键成果：**
- 将 API key 存储从明文迁移到 macOS Keychain
- 为网络故障实现了完整的错误处理
- 增加了 Sentry 崩溃上报集成
- 修复了自动刷新定时器中的内存泄漏

**统计：**
- 修改了 23 个文件
- 新增 650 行 Swift 代码
- 2 个阶段，3 个计划，12 个任务
- 从 v1.0 到 v1.1 共 8 天

**Git 范围：** `feat(05-01)` → `feat(06-02)`

**下一步：** v2.0 SwiftUI 重设计并支持小组件

---

## v1.0 MVP (Shipped: 2025-11-25)

**已交付：** 菜单栏天气应用，支持当前天气和 3 日预报

**已完成阶段：** 1-4（共 7 个计划）

**关键成果：**
- 带 popover UI 的菜单栏应用（AppKit）
- 集成 OpenWeather API 并支持自动刷新
- 显示当前天气及天气图标
- 提供包含最高/最低温的 3 日预报列表
- 已签名并完成公证，可用于分发

**统计：**
- 创建了 47 个文件
- 2,450 行 Swift 代码
- 4 个阶段，7 个计划，28 个任务
- 从开始到发布共 12 天

**Git 范围：** `feat(01-01)` → `feat(04-01)`

**下一步：** 为 v1.1 进行安全审计与加固
```
</example>

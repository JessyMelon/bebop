<purpose>
生成会后总结文档，记录本次会话完成的工作、达成的结果以及估算的资源使用情况。将 SESSION_REPORT.md 写入 `.planning/reports/`，供人工审阅和对外分享。
</purpose>

<required_reading>
开始前读取 invoking prompt 的 execution_context 中引用的所有文件。
</required_reading>

<process>

<step name="gather_session_data">
从可用来源收集会话数据：

1. **STATE.md** — 当前 phase、milestone、进度、阻塞项、决策
2. **Git log** — 本次会话期间的提交（最近 24 小时或自上次报告以来）
3. **Plan/Summary files** — 已执行的计划、已写出的总结
4. **ROADMAP.md** — milestone 背景和 phase 目标

```bash
# 获取最近的提交（过去 24 小时）
git log --oneline --since="24 hours ago" --no-merges 2>/dev/null || echo "No recent commits"

# 统计变更文件数
git diff --stat HEAD~10 HEAD 2>/dev/null | tail -1 || echo "No diff available"
```

读取 `.planning/STATE.md` 以获取：
- 当前 milestone 和 phase
- 进度百分比
- 活跃阻塞项
- 最近决策

读取 `.planning/ROADMAP.md` 以获取 milestone 名称和目标。

检查是否已有报告：
```bash
ls -la .planning/reports/SESSION_REPORT*.md 2>/dev/null || echo "No previous reports"
```
</step>

<step name="estimate_usage">
根据可观察信号估算 token 使用量：

- 无法直接获取 tool call 数量，因此根据 git 活动和文件操作估算
- 注意：这只是**估算值**，精确 token 数需要 API 级埋点，而 hooks 无法访问

估算启发式：
- 每个 commit ≈ 1 个 plan cycle（research + plan + execute + verify）
- 每个 plan file ≈ 2,000-5,000 tokens 的 agent 上下文
- 每个 summary file ≈ 1,000-2,000 个生成 token
- 每次 subagent 启动会按所用 agent 类型大致乘上 ~1.5x
</step>

<step name="generate_report">
创建报告目录和文件：

```bash
mkdir -p .planning/reports
```

写入 `.planning/reports/SESSION_REPORT.md`（若已存在旧报告，则写入 `.planning/reports/YYYYMMDD-session-report.md`）：

```markdown
# GSD Session Report

**Generated:** [timestamp]
**Project:** [from PROJECT.md title or directory name]
**Milestone:** [N] — [milestone name from ROADMAP.md]

---

## Session Summary

**Duration:** [estimated from first to last commit timestamp, or "Single session"]
**Phase Progress:** [from STATE.md]
**Plans Executed:** [count of summaries written this session]
**Commits Made:** [count from git log]

## Work Performed

### Phases Touched
[List phases worked on with brief description of what was done]

### Key Outcomes
[Bullet list of concrete deliverables: files created, features implemented, bugs fixed]

### Decisions Made
[From STATE.md decisions table, if any were added this session]

## Files Changed

[Summary of files modified, created, deleted — from git diff stat]

## Blockers & Open Items

[Active blockers from STATE.md]
[Any TODO items created during session]

## Estimated Resource Usage

| Metric | Estimate |
|--------|----------|
| Commits | [N] |
| Files changed | [N] |
| Plans executed | [N] |
| Subagents spawned | [estimated] |

> **Note:** Token and cost estimates require API-level instrumentation.
> These metrics reflect observable session activity only.

---

*Generated by `/gsd-session-report`*
```
</step>

<step name="display_result">
向用户展示：

```
## Session Report Generated

📄 `.planning/reports/[filename].md`

### Highlights
- **Commits:** [N]
- **Files changed:** [N]  
- **Phase progress:** [X]%
- **Plans executed:** [N]
```

如果这是第一份报告，补充提示：
```
💡 Run `/gsd-session-report` at the end of each session to build a history of project activity.
```
</step>

</process>

# Forensics Workflow

针对失败或卡住的 GSD 工作流进行事后调查。分析 git 历史、
`.planning/` 产物以及文件系统状态，以检测异常并生成结构化诊断报告。

**原则：** 这是一次只读调查。不要修改项目文件。
只写取证报告。

---

## Step 1: 获取问题描述

```bash
PROBLEM="$ARGUMENTS"
```

如果 `$ARGUMENTS` 为空，询问用户：
> "出了什么问题？请描述一下，例如：'autonomous mode got stuck on phase 3'、
> 'execute-phase failed silently'、'costs seem unusually high'。"

为报告记录问题描述。

## Step 2: 收集证据

从所有可用来源收集数据。来源缺失也没关系，根据现有内容调整。

### 2a. Git 历史

```bash
# Recent commits (last 30)
git log --oneline -30

# Commits with timestamps for gap analysis
git log --format="%H %ai %s" -30

# Files changed in recent commits (detect repeated edits)
git log --name-only --format="" -20 | sort | uniq -c | sort -rn | head -20

# Uncommitted work
git status --short
git diff --stat
```

记录：
- 提交时间线（日期、消息、频率）
- 编辑次数最多的文件（可能表示卡在循环中）
- 未提交的变更（可能表示崩溃/中断）

### 2b. 规划状态

如果这些文件存在，则读取：
- `.planning/STATE.md` — 当前里程碑、阶段、进度、阻塞项、最近会话
- `.planning/ROADMAP.md` — 带状态的阶段列表
- `.planning/config.json` — 工作流配置

提取：
- 当前阶段及其状态
- 最近记录的会话停止点
- 任何阻塞项或标记

### 2c. 阶段产物

对于 `.planning/phases/*/` 中的每个阶段目录：

```bash
ls .planning/phases/*/
```

对每个阶段，检查哪些产物存在：
- `{padded}-PLAN.md` 或 `{padded}-PLAN-*.md`（执行计划）
- `{padded}-SUMMARY.md`（完成摘要）
- `{padded}-VERIFICATION.md`（质量验证）
- `{padded}-CONTEXT.md`（设计决策）
- `{padded}-RESEARCH.md`（规划前研究）

跟踪：哪些阶段的产物完整，哪些存在缺口。

### 2d. 会话报告

如果 `.planning/reports/SESSION_REPORT.md` 存在，则读取并提取最近一次会话的结果、
已完成工作以及 token 估算。

### 2e. Git Worktree 状态

```bash
git worktree list
```

检查是否存在孤立 worktree（来自崩溃的代理）。

## Step 3: 检测异常

根据以下异常模式评估已收集的证据：

### 卡住循环检测

**信号：** 同一文件在很短时间窗口内出现在连续 3 次以上提交中。

```bash
# Look for files committed repeatedly in sequence
git log --name-only --format="---COMMIT---" -20
```

解析提交边界。如果任一文件出现在连续 3 次以上提交中，标记为：
- 如果提交消息相似（例如同一文件上反复出现 "fix:"、"fix:"、"fix:"），则 **Confidence HIGH**
- 如果文件频繁出现但提交消息不同，则 **Confidence MEDIUM**

### 缺失产物检测

**信号：** 阶段看起来已完成（有提交、在 roadmap 中已过去），但缺少预期产物。

对于每个应当已完成的阶段：
- PLAN.md 缺失 → 跳过了规划步骤
- SUMMARY.md 缺失 → 阶段未被正确收尾
- VERIFICATION.md 缺失 → 跳过了质量检查

### 被放弃工作检测

**信号：** 最近一次提交到当前时间间隔很长，且 STATE.md 显示执行进行到中途。

```bash
# Time since last commit
git log -1 --format="%ai"
```

如果 STATE.md 显示某个阶段正在进行，但最近一次提交已超过 2 小时，且存在
未提交变更，则标记为可能的放弃或崩溃。

### 崩溃/中断检测

**信号：** 未提交变更 + STATE.md 显示执行到中途 + 存在孤立 worktree。

组合判断：
- `git status` 显示 modified/staged 文件
- STATE.md 含有活动执行记录
- `git worktree list` 显示除主 worktree 之外的其他 worktrees

### 范围漂移检测

**信号：** 最近的提交触及当前阶段预期范围之外的文件。

读取当前阶段的 PLAN.md，以确定预期文件路径。与最近提交中实际修改的
文件进行对比。标记所有明显超出该阶段领域范围的文件。

### 测试回归检测

**信号：** 提交消息包含 "fix test"、"revert"，或测试文件被重复提交。

```bash
git log --oneline -20 | grep -iE "fix test|revert|broken|regression|fail"
```

## Step 4: 生成报告

如有需要，创建 forensics 目录：
```bash
mkdir -p .planning/forensics
```

写入 `.planning/forensics/report-$(date +%Y%m%d-%H%M%S).md`：

```markdown
# Forensic Report

**Generated:** {ISO timestamp}
**Problem:** {user's description}

---

## Evidence Summary

### Git Activity
- **Last commit:** {date} — "{message}"
- **Commits (last 30):** {count}
- **Time span:** {earliest} → {latest}
- **Uncommitted changes:** {yes/no — list if yes}
- **Active worktrees:** {count — list if >1}

### Planning State
- **Current milestone:** {version or "none"}
- **Current phase:** {number — name — status}
- **Last session:** {stopped_at from STATE.md}
- **Blockers:** {any flags from STATE.md}

### Artifact Completeness
| Phase | PLAN | CONTEXT | RESEARCH | SUMMARY | VERIFICATION |
|-------|------|---------|----------|---------|-------------|
{for each phase: name | ✅/❌ per artifact}

## Anomalies Detected

### {Anomaly Type} — {Confidence: HIGH/MEDIUM/LOW}
**Evidence:** {specific commits, files, or state data}
**Interpretation:** {what this likely means}

{repeat for each anomaly found}

## Root Cause Hypothesis

根据上述证据，最可能的解释是：

{1-3 sentence hypothesis grounded in the anomalies}

## Recommended Actions

1. {Specific, actionable remediation step}
2. {Another step if applicable}
3. {Recovery command if applicable — e.g., `/gsd-resume-work`, `/gsd-execute-phase N`}

---

*Report generated by `/gsd-forensics`. All paths redacted for portability.*
```

**脱敏规则：**
- 将绝对路径替换为相对路径（去掉 `$HOME` 前缀）
- 移除 git diff 输出中发现的任何 API keys、tokens 或 credentials
- 大型 diff 截断为前 50 行

## Step 5: 展示报告

直接内联显示完整取证报告。

## Step 6: 提供交互式调查

> "报告已保存到 `.planning/forensics/report-{timestamp}.md`。
>
> 我可以继续深入任何一个发现。要我：
> - 追踪某个特定异常的根因？
> - 读取证据中引用的特定文件？
> - 检查之前是否报告过类似问题？"

如果用户提出后续问题，基于已收集的证据回答。
仅在确有需要时再读取其他文件。

## Step 7: 提供创建 Issue

如果发现了可执行的异常（HIGH 或 MEDIUM 置信度）：

> "要我为此创建一个 GitHub issue 吗？我会整理这些发现并对路径进行脱敏。"

如果确认：
```bash
# Check if "bug" label exists before using it
BUG_LABEL=$(gh label list --search "bug" --json name -q '.[0].name' 2>/dev/null)
LABEL_FLAG=""
if [ -n "$BUG_LABEL" ]; then
  LABEL_FLAG="--label bug"
fi

gh issue create \
  --title "bug: {concise description from anomaly}" \
  $LABEL_FLAG \
  --body "{formatted findings from report}"
```

## Step 8: 更新 STATE.md

```bash
gsd-sdk query state.record-session "" \
  "Forensic investigation complete" \
  ".planning/forensics/report-{timestamp}.md"
```
